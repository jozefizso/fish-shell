# Tests, benchmarks, and CI

## Scope and evidence boundary

This page covers Rust unit/doctests/benchmarks, every top-level `tests/` family, the complete shell benchmark workload set, all eight GitHub workflows and five local action families, all four `.builds` configurations, Docker and BSD Vagrant tooling. [`coverage.md`](coverage.md) contains the file-level inventory; named checks below illustrate mechanisms within those complete families rather than stand in for all tests.

No tests, builds, benchmarks, linters, workflows, containers, VMs or native terminal experiments were run for this audit. Every Windows scenario below is **proposed acceptance work**, not evidence of a passing implementation. Existing workflows are analyzed as source, not claimed to have run successfully.

## Benchmark components: complete local workload set

The existing runner is [`benchmarks/driver.sh`](../../benchmarks/driver.sh), called by [`cmake/Benchmark.cmake`](../../cmake/Benchmark.cmake). It uses POSIX shell quoting implemented with `sed`, optional `hyperfine` command strings, `/dev/null`, and fish `--print-rusage-self`. Native execution needs a host-portable runner and Windows timing/resource counters (for example `GetProcessTimes`/`GetProcessMemoryInfo` for relevant metrics); they do not yield a field-for-field POSIX `rusage` replacement. Wall-clock measurements need a monotonic source. The driver does not currently provide a comprehensive reader/history benchmark suite.

All workload files in [`benchmarks/benchmarks/`](../../benchmarks/benchmarks/) are accounted for here:

| Workloads | Mechanism/POSIX assumptions | Windows equivalent and proposed validation |
|---|---|---|
| [`aliases.fish`](../../benchmarks/benchmarks/aliases.fish), [`no_execute.fish`](../../benchmarks/benchmarks/no_execute.fish) | Large alias/function script is also the `fish -n` parse workload; no-execute repeatedly starts fish and uses `seq`. | No Win32 API for parsing; native process backend for repeated invocation. Compare same input/version and native executable quoting. |
| [`external_cmds.fish`](../../benchmarks/benchmarks/external_cmds.fish) | Repeated **external** `command true`, with external `seq`; depends on Unix utilities, not just fish builtin `true`. | Use an explicit native no-op child helper to measure actual process launch, not a builtin/mock. Report that workload change when comparing. |
| [`glob.fish`](../../benchmarks/benchmarks/glob.fish), [`load_completions.fish`](../../benchmarks/benchmarks/load_completions.fish) | Recursively traverses this repository; completion loading sources files only for commands found on PATH. Results depend on checkout size and installed commands. | Native enumeration/path/executable lookup; no extra API for completion parsing. Fix checkout/input/tool inventory for comparisons, and separately measure UNC/network paths and `PATHEXT` lookup. |
| [`math.fish`](../../benchmarks/benchmarks/math.fish), [`set_long.fish`](../../benchmarks/benchmarks/set_long.fish), [`seq_echo.fish`](../../benchmarks/benchmarks/seq_echo.fish) | Arithmetic/local-variable/echo loops, initial external `seq` generation. | No Win32 API for core operations; replace/control sequence-generator prerequisite explicitly. | [`read.fish`](../../benchmarks/benchmarks/read.fish) | External `mktemp`, `cat`, `seq`, temp file and repeated pipeline into `read`. | Native filesystem/process/pipe implementations plus equivalent helpers. Rust nightly benchmarks are separate: [`ast.rs::bench_ast_construction`](../../src/ast.rs) and [`common.rs::bench_convert_ascii`](../../src/common.rs), gated by `all(nightly, feature = "benchmark")` and `cfg(test)`; root [`lib.rs`](../../src/lib.rs) enables the unstable `test` feature accordingly. Those algorithms need no direct Windows API but still compile their crate graph. Proposed validation is actual native nightly benchmark execution with input/version held fixed, not assuming stable `cargo test` exercised them.

Useful additional **proposed**, not preexisting, native workloads are pipeline launch, directory/PATH/PATHEXT lookup, ConPTY repaint/resize, universal-variable notification latency and concurrent history rewrite. Resource measurements must identify native MSVC versus MSYS2, terminal versus pipe output, architecture, filesystem, antivirus/indexing effects and fixture/tool inventories.

## Native acceptance layers

A native Windows gate must exercise actual APIs and processes, not substitute mock output or call a POSIX implementation through MSYS:

1. **Algorithms and CLI:** native unit/doctests; `fish_indent.exe` valid/malformed input; `fish.exe -c` variables, substitutions, pipeline/redirection, exact child exit codes and arbitrary redirected bytes. Parameterize genuinely different native path spelling while preserving language results.
2. **Process/handle backend:** allowlisted inherited handles, unrelated-handle nonleakage, pipeline EOF after all copies close, async I/O/cancellation where used, process waits and Job Object lifecycle/disown policy. Ctrl events are not POSIX signal numbers; test the specified native contract.
3. **Filesystem/state:** drive/UNC/long/non-BMP/lone-surrogate names where constructible, case-sensitive directories, symlink/junction capabilities, sharing/locks/atomic replacement/open readers, concurrent history writers, two-shell universal-variable propagation and notification overflow recovery. Windows ACL results must not masquerade as mode-bit tests.
4. **Environment/localization:** case collisions, large UTF-16 environment blocks, language precedence and numeric separators, packaged and feature-disabled catalogs/help, PATH/PATHEXT and source-independent resource discovery.
5. **Terminal:** real ConPTY startup, Unicode/key/completion/pager input, resize/repaint, Ctrl-C, EOF and clean console-mode restoration on exit/error; classic direct console only if supported. POSIX stop/continue/tty ownership remains a separate Unix contract.
6. **Distribution and tooling:** native-host build/doc/localization tools, all three packaged executable names, ordinary-user install/extract under a Unicode/space path, no hidden POSIX shell dependency and upgrade/state preservation. CI should capture native output/failures and list intentionally skipped capabilities.

These layers are requirements for a future implementation, **not commands/results observed here**. Compilation alone cannot validate handle inheritance, terminal restoration, path identity or multi-process state persistence. Likewise a green guest/MSYS workflow cannot establish any of those native Win32 semantics.

## Classification

Rust/Python test organization and data-driven assertions are reusable. Current driver startup, littlecheck shell execution, helper C binary, PTY/tmux transports, shell benchmark runner and host CI provisioning have concrete POSIX assumptions. Add native transport/helper/backend coverage while retaining intentional Unix suites; report every skip and separate native-MSVC, MSYS/Cygwin, WSL and guest-OS evidence.
