# Builtins

## Current native registry and option ownership

The native source registry currently enables `[`, `cd`, `command`, `path`, `pwd`, `realpath`,
`test`, `type` alongside prototype `echo`, `exit`, `false`, `math`, `printf`, `set`, `true`.
N1 additions are implemented and exercised for the recorded native development matrix. Source
inclusion alone does not establish other capabilities: remaining reserved spellings are rejected, and many
implementation modules remain Unix-only. `return.rs` is compiled for shared exit-value parsing
without registering native `return`. Functions/autoload/highlight/help are not implied by `type`.

The authoritative [option/subcommand ledger](coverage.md#builtin-option-and-subcommand-ledger)
enumerates each builtin flag/alias/subcommand, its current supported/rejected/unavailable
state, required semantics and owner. The [executable CLI ledger](coverage.md#executable-cli-option-ledger)
also covers every fish, fish_indent and fish_key_reader option, including their builtin tool
spellings. The native formatter/key-reader executable stubs still reject all use.

Ordinary filesystem namespaces, metadata, timestamps/same-file and native permission options are
N1; Unix-only identity/mode/device options and quotas are N8; help is N9. Portable batch/string/
function/event options belong to N3, persistence/startup to N4, jobs/accounting to N5, reader tools
to N6 and evaluated completion/advanced editing to N7. POSIX `exec`, `fg`, `bg` remain permanently
unsupported with reserved-name rejection and no external fallback. Faithful POSIX fork is excluded.
N11 reconciles these owners' completed behavior, not a new destination for missing options.

Prototype option restrictions remain material: math flags are rejected despite the parser code;
set accepts only its local/global/export/unexport/query/erase subset; true/false reject additional
operands; help tooling is unavailable. N1 `path/test` ordinary types/access use the shared native
metadata/classification services, while Unix-only type/ownership/mode predicates explicitly fail
instead of silently succeeding through compiled-out branches. See the
[N1 option table](coverage.md#n1-filesystemdiscovery-options) for every operand/flag category.

The [N1 evidence record](coverage.md#n1-verified-evidence-record) records passing debug/release
gates, minimum-Rust executable verification, native/Unix regressions and actual runtime smokes.
Required fixture absence hard-fails acceptance, not a skip; unsupported volume case/identity
queries remain explicit errors. Historical prototype results in GOAL.md remain unchanged.
`cd -`/directory history is supplied by shipped fish functions and remains N4/N9 integration,
not a second native builtin history implementation.

## Historical scope, inventory, and platform boundary

The following original audit covers every then-declared module in [`builtins/mod.rs`](../../src/builtins/mod.rs), nested `string/`/`shared/` modules and Unix registered spellings in [`shared/misc.rs::BUILTIN_DATAS`](../../src/builtins/shared/misc.rs). It describes original implementation dependencies and candidate replacements, not the current native registry. Verification scenarios are proposed checks, **not results**.

**Pure** means no builtin-specific Linux syscall, not that the present Unix-based common types already compile on Windows. All commands still depend on `IoStreams`, text conversion, status and localization; help can evaluate `__fish_print_help`. **Delegated** means OS work occurs in parser/process/path/environment/history/terminal services and must be ported there, rather than adding a second Win32 implementation to each builtin. `funcsave` and `trap` are shipped functions, not missing Rust builtin modules. `exec` and `time` are parser-handled decorators, not separate `exec.rs`/`time.rs` builtin modules.

Shared backends: [process/job control](03-process-execution-job-control.md), [signals/events/accounting/limits](04-signals-events-waits.md), [I/O](05-io-redirection-file-descriptors.md), [terminal/editor](06-terminal-reader-screen-input.md), [filesystem/path](07-filesystem-paths-wildcards.md), [environment](08-environment-and-universal-variables.md), [history/functions](09-history-functions-autoload.md), [text/regex/locale](11-text-regex-localization.md). The full repository manifest is [coverage.md](coverage.md).

## Shared modules, aliases, and parser-owned spellings

- [`shared/mod.rs`](../../src/builtins/shared/mod.rs) reexports `error` and `misc`; no native work itself.
- [`shared/error.rs::Error`, `write_to`, `finish`](../../src/builtins/shared/error.rs) compose localized messages, hints and optional parser stack traces into `OutputStream`; **no direct Linux syscall**. Reuse on Windows; verify Unicode errors, redirected stderr and help trailers.
- [`shared/misc.rs::builtin_run`, `BUILTIN_DATAS`, `builtin_lookup`, `builtin_get_names`, `BuiltinResult`, `HelpOnlyCmdOpts`, `parse_pid`, `builtin_break_continue`, `ColorEnabled`](../../src/builtins/shared/misc.rs) provide registry/dispatch, status, option parsing, loop state, typed PID parsing and output policy. Pure except delegated streams/parser/event/terminal services. PID parsing must represent native IDs without treating IDs as HANDLEs; terminal-auto coloring must use native endpoint detection.
- [`shared/misc.rs::Arguments`, `ArgvSource`, `SplitBehavior`, `InputValue`](../../src/builtins/shared/misc.rs) read argv or `BufReader<BorrowedFdFile>`, preserving newline/NUL/no-final-newline and InferNull semantics. This is shared **delegated I/O**, not pure argv parsing. Native input adapter should preserve data exactly; test newline/NUL inference, closed stdin and partial multibyte input across buffer boundaries.
- [`builtin_print_help`](../../src/builtins/shared/misc.rs) evaluates `__fish_print_help` through the parser. Its surrounding script/help tools are not made native merely by compiling the core builtin. Verify unavailable viewer/external tool diagnostics separately; do not substitute PowerShell or cmd silently.
- Registered aliases are **`.` → source**, **`:` → true**, **`[` → test**, **`_` → gettext**. There is no registered `gettext` spelling in `BUILTIN_DATAS`.
- `builtin_generic` marks parser-owned registered spellings: **`!`, `and`, `begin`, `case`, `else`, `end`, `exec`, `for`, `function`, `if`, `not`, `or`, `switch`, `time`, `while`**. Control grammar has no additional Linux dependency; evaluated commands use shared backends. `function` has its dedicated special entry above; `exec` depends on non-equivalent image replacement, and `time` on [`timer.rs::TimerSnapshot`](../../src/timer.rs) accounting, not a timer scheduler. Test parser dispatch/decorator precedence rather than trying to call these through an ordinary builtin function pointer.

| `normalize` / `path_normalize`, `normalize_help` | Lexical normalization, no metadata lookup; Unix slash/root and leading-dash handling need native policy. | Nonexistent components, `..`, drive-relative path and leading `-`. |
| `sort` / `path_sort` | In-memory stable `wcsfilecmp_glob` sorting with lexical key extraction (basename/dirname/path), reverse and unique; **no filesystem metadata lookup**. | Numeric filename ordering, chosen key, case ties, reverse/unique and empty records. |
| `filter` / `path_filter`, `filter_path` | `wstat/lwstat/waccess`, Unix file kinds, effective owner/group and setuid/setgid checks; native metadata/access/token/reparse policy required. | Missing target, symlink, native device, permissions and owner checks. |
| `is` / `path_is`, `path_filter_maybe_is` | Same filesystem checks, quiet and optional all-input policy; no separate OS primitive. | Mixed matching/nonmatching inputs, all/any, no output and exit status. |
| `mtime` / `path_mtime` | `file_id_for_path` supplies metadata modification time; relative mode uses SystemTime. Native file timestamps must use consistent epoch/units. | Missing file, future timestamp, relative age and subsecond/epoch conversion. |
| `resolve` / `path_resolve` | `wrealpath`; on failure walks ancestors then normalizes remaining suffix, including nonexistent/non-directory components. Native canonicalization/reparse policy is not simply “target must exist”. | Missing leaf/parent, `file/../`, link/junction loop, relative/UNC and quiet mode. |

[`test.rs::test_expressions`](../../src/builtins/test.rs) includes file kind, symlink, size, access, effective UID/GID, setuid/setgid/sticky, tty, timestamp comparisons and same-file identity; numeric/string/boolean expressions need no Windows API. Proposed policy must be explicit:

- Regular file/directory: native attributes/handle metadata; symlink: recognized reparse tags, not every reparse point. Device/pipe/socket predicates have no general NTFS-mode-bit equivalent; decide supported handle/path kinds rather than asserting every character device is false (`NUL`/console are native device examples).
- Read/write/execute checks: current POSIX `access` policy is not automatically an ACL query. Safe attempted open, ACL/token access checks and command-resolution policy each answer different questions. An extension-based executable predicate may be a useful native contract, but must be documented as changed semantics and used consistently by `test`, `path`, `command`, `type` and launch.
- UID/GID and setuid/setgid/sticky: no faithful universal integer/mode mapping; return explicit unsupported or documented predicate-false behavior, not invented Unix ownership. Windows SIDs/ACLs are different models.
- `-ef`/same-file: volume serial plus file ID from handle information, not string canonicalization alone; `-nt/-ot` use comparable timestamp units and missing-file behavior. Tty tests must honor redirection flags and logical fd mapping.

## Classification

Most builtin-specific algorithms are **portable**, but many apparently pure commands can evaluate fish code, autoload functions, read redirected input or request completion. Platform work is **delegated** to common backends; direct POSIX-heavy builtins (`cd`, `read`, `test`, `path`, `ulimit`, job control and terminal tools) require explicit native semantics. The inventory above includes every top-level and nested module plus registered aliases/parser-owned forms; it does not imply any native Windows checks have run.
