# Environment, configuration paths, and universal variables

## Scope and evidence

This source-grounded audit accounts for every `env/` and `universal_notifier/` module, plus `env_dispatch.rs` and `env_universal_common.rs`. Windows APIs describe proposed native behavior, not existing backends. No build, notifier experiment or Windows runtime test was performed. Filesystem locking/replacement is audited in [07](07-filesystem-paths-wildcards.md); the full module inventory is in [coverage](coverage.md).

## Native environment policy

`CreateProcessW` accepts an explicit environment block and `CREATE_UNICODE_ENVIRONMENT` marks its UTF-16 interpretation. Build `name=value\0...\0\0` entries in the documented case-insensitive Unicode ordering, not locale-dependent sorting; keep the final double terminator even for an empty environment. Native names/values cannot contain embedded NUL; ordinary names cannot contain `=`. Hidden drive-current-directory entries beginning with `=` require explicit preservation or rejection policy rather than accidental treatment as ordinary fish variables.

Fish's internal scopes are case-sensitive, while native exported lookup is case-insensitive. Resolve `Path`/`PATH` and other collisions before constructing a child block. Import/export canonicalization of known names is one possible policy, but it must not unpredictably change scope precedence or map two independent local values to duplicate native names. Preserve raw inherited data only with the intended encoding; native UTF-16 can contain code units not representable as Unicode scalars.

Keep lists internally. Windows PATH normally uses semicolons, but drive-letter colons mean the existing `colon_split` cannot run first and be repaired later. Since current pathvar behavior also affects assignments and string expansion, define those operations end-to-end, including custom `*PATH` variables, `LANGUAGE`, CDPATH/MANPATH and cross-platform persisted lists. Not every variable ending in PATH necessarily has native Windows path-list semantics. Native child launch should not mutate the parent environment simply to pass exported values, but locale/timezone hooks still need coherent CRT/Win32 state.

## Identity and configuration policy

- USER can come from `GetUserNameW`/`GetUserNameExW` with a deliberately selected display/account-name form; token SID identifies the security principal. Neither provides a numeric Unix EUID. HOME can use `SHGetKnownFolderPath(FOLDERID_Profile)` or token/profile APIs with inherited-override policy matching the intended behavior. Do not overwrite an intentionally inherited HOME just because it differs from the profile directory.
- `GetCurrentProcessId` maps fish_pid; `GetComputerNameExW` supplies a chosen DNS/NetBIOS hostname form. Status/pipestatus remain shell values but Unix signal termination fields require the process backend's native definition.
- `SHGetKnownFolderPath` for `FOLDERID_LocalAppData` or `FOLDERID_RoamingAppData` can provide user-state roots. Config, history/data, cache and universal-state location must be chosen explicitly. The current default `fish_variables` follows the config root. Do not simultaneously recommend roaming storage as the default and call it safely machine-local: roaming introduces multi-machine writers, and local filesystem locks do not coordinate their synchronization service.
- Continue honoring applicable global-exported XDG overrides under a chosen native absolute-path policy; source startup intentionally avoids universal XDG/HOME lookup before uvars exist to prevent lock inversion. Builtin default directory permissions `0700` are not equivalent to inherited Windows DACLs. Bundled data/system paths in `ConfigPaths` are a separate installation-layout concern.

## Universal synchronization and notifications

`EnvUniversal::sync` merges pending local changes with on-disk state through the filesystem rewrite callback, advances export generations and emits variable-change callbacks. An unchanged `FileId` avoids reading; future-format files are not overwritten. A Windows port must preserve those behaviors and the lockless limitations of the selected storage backend. Atomic replacement means watch the **directory**, not merely a handle to the old data file.

For a proposed `ReadDirectoryChangesW` backend, open the directory with appropriate sharing and overlapped flags, request relevant filename/write/size changes, filter target names and treat notifications as hints to reread metadata/content. Queue/re-arm requests and cancel/close them with explicit lifetime rules. A successful completion with lost detail, notification overflow (`ERROR_NOTIFY_ENUM_DIR`/zero returned bytes as applicable), deleted parent or disconnected network path requires re-enumeration/reopening policy. Any periodic recovery check would be new native behavior, not something `NullNotifier` already provides. Network buffer constraints and absent guarantees about event coalescing make “one event per variable update” an invalid contract.

## Windows validation scenarios

These scenarios are proposed acceptance work, not checks performed in this audit.

- **E1 — Scope and native export:** exercise local/function/global/universal values, readonly/electric variables, snapshots, exported flags, scope pop and uvar-generation invalidation. Import/export `Path` and `PATH`, Unicode names/values, empty variables and explicitly supported hidden drive entries. Launch a real native child and inspect the UTF-16 environment rather than using a Unix `envp` mock; no duplicate-case exports or process-global launch mutation.
- **E2 — Paths and startup:** use drive/UNC/extended paths, semicolons, spaces and drive-letter colons in PATH, HOME/PWD, XDG roots and persisted pathvars; compare assignment, string expansion and native export. Check LANGUAGE separately. Move an installation/build tree and verify bundled assets independently of user known-folder state. Check logical inherited PWD identity and `--no-config`'s global-instead-of-universal behavior.
- **E3 — Identity and unsupported Unix state:** test ordinary/elevated tokens, deliberate HOME override, missing USER/HOME, domain/local account names and non-ASCII profile paths. EUID, umask and fish_kill_signal must have explicit native behavior rather than invented numeric equivalence; newly created file security must match any promised policy.
- **E4 — Reactions:** change/unset LANG/LC/TZ during background work and verify lock ordering, locale precedence, numeric-cache invalidation and actual formatted time/number behavior. Change terminal widths/delays, search paths, history, reader settings, tracing and read limits; verify their consumers update without deadlock or redundant repaint. POSIX spawn preference must not falsely describe the native launcher.
- **E5 — Persisted state:** start independent native fish processes, modify different and identical uvar keys, unset keys, preserve flags and restart. Check empty list vs empty string, escaped UTF-8, record-separator arrays, older/future versions and the read cap. Inject sharing/replacement failures and rapid equal-size changes; changes must not be claimed saved merely because a notification occurred.
- **E6 — Notification integration:** keep several readers blocked while replacing `fish_variables`; every reader must wake and synchronize. Exercise unrelated directory writes, burst coalescing, initial file absence, file deletion/recreation, overflow, backend creation failure, parent rename/removal, network loss and reader shutdown during pending I/O. Assert no lost invalidation, leaked handle, wakeup spin or reliance on POSIX fd readiness for HANDLEs. Any recovery guarantee must be tested against the implemented recovery mechanism.

## Classification

Scoped/list/electric-variable infrastructure and most persistence-format logic are portable algorithms. Import/export encoding, path delimiters/roots, startup identity, installation/user directories, umask/signal-derived values, locale/timezone side effects, synchronized storage and notifier integration are POSIX-backed. inotify is Linux/Android-specialized; notifyd and kqueue demonstrate separate Apple/BSD implementations, not a universal POSIX or native Windows fallback.
