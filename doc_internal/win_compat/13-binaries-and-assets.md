# Binaries and shipped fish assets

## N9 asset/tool implementation and remaining evidence boundary

The file-level [N9 ledger](n9-assets.tsv) enumerates all 1,425 shipped files:
277 functions, 1,097 completions, 13 prompts, 25 themes, 9 Python/web assets,
`etc/config.fish` and the three `share/` root files. It records native-runtime,
optional-native-tool, or genuinely platform-inapplicable dispositions, concrete
consumer/dependency requirements and the owning behavior case. These are source
dispositions, **not** substituted `native-tested` claims: `evidence=not-run` is
intentional until native execution is recorded. `REQUIRED:` identifies 976
still-uncovered applicable per-file consumer requirements; neither dormant source,
load/parse success nor a static flag test closes a dynamic provider.
The N9-ASSETS inventory family fails while any `REQUIRED:` row remains; executing
the 314 static cases alone cannot certify the shipped collection.
These are untriaged executable-coverage obligations, not 976 confirmed code defects
or unavailable external dependencies. Aliases, static conditional tables, pure fish
helpers and supported-but-unexercised native tool integrations remain among them.
Their source classifications must be refined alongside real consumer assertions.

Native extraction now uses private native temporary directories, native recursive
directory creation and owned deletion on normal/error return. `funced` preserves
editor argv, uses a fixed private `.fish` filename, compares complete text without
external checksum tools, reads through native byte streams and atomically saves.
Editor-reported cancellation and failed saves propagate failure and remove their
workspace. Native cache readers/writers no longer require `cat`, `touch`, `chown`,
`stat`, `mkdir`, `rm` or `/bin/sh`; generated-script caches retain the previous
complete file on generator failure and invalidate on executable identity/mtime.
`fish_delta` has a builtin stream fallback rather than mandatory `cat`.

Account/process/network/drive consumers reuse N8 native services; Windows-oriented
`cmd`, `cmdkey`, `reg` and `schtasks` completion paths no longer require WMIC,
`awk`, `tail` or `tr` on native Windows. `open` passes literal items to native shell
associations, while unsupported Unix signal/stop wrappers return explicit errors.
All sample prompt date displays use the native timestamp service where applicable;
Acidhub and SVN status formatting use fish builtins rather than coreutils.

Native rustup completion providers use fish set membership and recursive globs,
strip actual target suffixes rather than a Linux-only host suffix, keep toolchain
option/value argv separate, and normalize native documentation paths. Its component
and documentation consumers have real provisioned-rustup and absent-tool cases;
no Unix `comm`, `sort`, `find` or temporary substitution protocol is required.
Cargo dynamic probes first check the actual wrapped executable and do not invoke a
JSON decoder when Cargo is absent. Python JSON readers explicitly use UTF-8; real
manifest-feature/package and absent-Cargo consumers run against the existing native
toolchain. Native parent traversal uses path primitives rather than splitting on
Unix `/`; an actual nested npm manifest lookup covers drive/Unicode preservation.

Optional Python tools require Python 3.8+ and probe actual interpreter versions,
including native `python.exe` and the Python launcher. The web tool receives the
calling image from `status fish-path`, uses its builtin formatter, binds loopback,
retains random-key authorization and rejects non-whitelisted peers. Private
redirect files are closed before browser access and removed in `finally`; input
workers are cancellable, HTTP workers are joined, request reads are bounded, and
owned fish/browser children are reaped. Native browser overrides use Windows argv
quoting, not shell strings or colon splitting. The previous Python-3.12-only
`delete_on_close` requirement is removed.

Manual generation accepts real plain/gzip/bzip2/xz/lzma roff inputs, preserves UTF-8
with legacy Latin-1 fallback, publishes complete scripts atomically and reports
missing/corrupt input as failure. Native manual discovery uses explicit files or
semicolon-separated `MANPATH`, never an invented Win32 manual inventory. Background
generation uses N5 native disown with a private program copy owned/removed by the
Python child; no shell-hosted stdin bridge must survive the initiating shell.
Sphinx/catalog build ownership and matching packaged help remain with N9 help/N10.

Authored tests are `tests/windows_n9/assets.rs` (13 families, including 314 actual
static completion-flag consumers and real isolated clipboard consumers) and
`tools.rs` (5 families, actual Python/manpage/browser/HTTP/lifetime consumers).
They require the native Python floor and below-floor fixtures, Playwright with a
native Edge/Chromium executable, all six native VCS dependencies (SVN also needs
`svnadmin`/`svnversion`), and the existing fresh-logon clipboard fixture. No test,
build or runtime pass is asserted by this implementation overlay.

Helper files/directories now attach fs-owned capabilities to the existing N5/N8
Job/caller lease protocol. Function return, error and Ctrl-C unwind release the
owner, while accepted argv/env/descendant, cwd and redirected-file consumers retain
their pre-resume acknowledgments. The detached updater explicitly calls
`transfer-temp-file` only after successful disown, including the fast-completed-child
case. Atomic writes check cancellation before reading and before commit instead of
publishing a producer's partial EOF. The N9 probe drives real owned-console Ctrl-C
through blocked `funced`, extraction, generated-cache and atomic-save workflows,
then asserts child exit, prompt recovery, exact modes and resource cleanup. These
are authored executable regressions, not an asserted native pass.

## Current N4 startup/core-assets overlay

Native fish now supports normal config → ordered init commands → command/script/stdin execution;
`-N` skips config but retains `-C` and private history, `-P` selects private history, `-l` and
default/query status expose real login state, and `--profile-startup` measures real stages.
`-n` avoids config/init/persistent-state effects. N6 enables the real interactive/key-reader entrypoints; installed help remains N9.

`env/config_paths.rs` locates executable-relative install assets independently of
`path/windows_config.rs` user config/data/cache roots. `wutil/windows.rs::native_current_exe_path`
handles trusted OS image spelling, including literal extended install roots, without relaxing
user-path validation. Core `share/config.fish` bootstrap is utility-free with native paths,
ordered conf.d basename masks, path-list policy and no Unix-only startup probes on Windows.
Full ordered disk/embedded autoload preserves overrides/tombstones and generated-completion
precedence. Public `funcsave` uses `builtins/native_fs.rs` atomic writes, mkdir and removal,
not external coreutils. Embedded `status get-file/list-files` are real core resource consumers.

N6 ports required utility-free first-prompt/default-binding helpers and native
clipboard/private editor-temp services; see its current evidence below. This is
not complete per-file asset certification: N7 completion/editor parity, N8
platform/providers/psub and N9 remaining helpers, optional external editors,
help/catalogs and user tools retain ownership. Earlier N3 evidence and
the original candidate audit/counts below remain historical. See the
[N4 record](coverage.md#n4-implementation-and-evidence-record) for final combined results.

The [N6 reader overlay](06-terminal-reader-screen-input.md#current-n6-native-reader-overlay)
documents actual console transport and tools; [GOAL_06](GOAL_06.md#implementation-and-verified-evidence)
records verified N6 console cases. Default-feature compilation
with missing Sphinx/msgfmt is not successful help/catalog generation.

## Current N5 binary/lifecycle consumers

`bin/fish/windows.rs` owns native console-control registration through shutdown and real
`--print-rusage-self` shell-only reporting on stderr. Reports use native elapsed/user/kernel
seconds, memory bytes, combined faults and I/O operations/bytes, with unavailable POSIX
categories named explicitly; they are not POSIX rusage fields filled with zero. `time`
uses actual fish plus completed/live tracked-job CPU at explicit accounting cutoffs.

Native `&`, `jobs`, `wait`, `disown` and process/job/caller/shell-exit functions now have
retained-handle lifecycle owners. Callbacks dispatch on the evaluator thread; control
callbacks only hand off atomics/events. Ordinary accepted/disowned processes survive
fish-owned Job Object closure, but shell-hosted pipe/bridge services do not survive fish.
This does not certify every shipped process facade/provider: POSIX `fg`/`bg` and suspension
remain permanently EXCLUDED with no reattachment emulation or external reserved-name fallback;
arbitrary Unix `kill`/trap delivery and provider dependencies are not supplied by native
Ctrl-Break support. N6–N11 asset/editor/terminal certification remains unchanged.

See [process contracts](03-process-execution-job-control.md#current-n5-native-lifecycle-contract),
[control/accounting](04-signals-events-waits.md#current-n5-control-and-accounting-contract)
and the [N5 implementation and evidence record](coverage.md#n5-implementation-and-evidence-record).
These source overlays do not declare all N5 gates passed or revise earlier proof.

## Verified N3 implementation

`bin/fish/windows.rs` now runs repeated command strings, scripts and stdin through the shared
noninteractive evaluator with `-N`, explicit argv/`--`, parse-only/features/version and real
debug/category/trace/profile output. Retired `-D` is a nonzero diagnostic, not ignored success.
Standalone and builtin `fish_indent` share real non-help stream/file/check/write/ANSI/HTML/token modes.
At the N3 cutoff normal utility-free startup/autoload/save remained N4; these are now delivered
above. The then-validator-only embedded exposure was not a complete asset audit, nor is N4.
See [N3's executable option mapping and artifacts](coverage.md#n3-verified-evidence-record).

## Historical scope and evidence

This source audit covers all `share/` and `etc/` **asset families**, including executable helpers rather than just static option tables. The [coverage ledger](coverage.md) inventories individual files. Source examples below establish dependencies and behavior; they are not claims that every third-party command variant has been executed. Native Windows means no assumed WSL, Cygwin, MSYS, coreutils or `/bin/sh` installation.

The roots are [`src/bin/`](../../src/bin), [`share/config.fish`](../../share/config.fish), [`share/__fish_build_paths.fish.in`](../../share/__fish_build_paths.fish.in), [`share/help_sections`](../../share/help_sections), [`functions/`](../../share/functions), [`completions/`](../../share/completions), [`prompts/`](../../share/prompts), [`themes/`](../../share/themes), [`tools/`](../../share/tools), and [`etc/config.fish`](../../etc/config.fish). The tables distinguish **no direct host API**, **host-backed builtin**, **external utility**, and **OS-specific integration**: fish syntax alone does not imply platform independence.

## Native distribution boundary and open questions

- Preserve extensionless **fish function/completion identities** while resolving `.exe`/`.cmd` process names intentionally. Existing Cygwin suffix handling is useful evidence but not a complete native command policy.
- Startup scripts are product behavior. A compiling executable whose first prompt requires `mkdir`, Python detachment through `/bin/sh`, or theme migration through `sleep` has not achieved native-only operation.
- Do not indiscriminately remove Unix completions: dormant static tables are different from active Linux probes. Keep cross-platform/native definitions and audit/gate executable providers at their actual call sites.
- No `/etc/shells` registration, login-shell installation assumption, privileged symlink requirement or compatibility-environment path translation is needed merely to distribute the native binaries and embedded data. Actual installation layout is covered in [15](15-build-packaging-documentation.md).
- Proposed Win32 APIs describe capabilities, not CLI replacements. Open decisions include POSIX job/signal exposure, FIFO `psub` consumer compatibility, native account/permission semantics, man rendering, executable-extension policy, native Python discovery/version floor, and which third-party utilities are intentionally optional dependencies.
- The original audit used source inventory and targeted reads across asset families without executing its proposed scenarios. N3 and current N4 overlays distinguish executable/bootstrap/autoload/funcsave support from third-party tools, help and complete per-file shipped-asset certification at their named owners.
